# 宠物社交 Web 应用 · 产品方案 v1

> 状态：草案，待确认
> 目标：1–2 周内做出一个可演示、可分享链接的完整作品

---

## 1. 一句话定位

**给城市里独自遛狗的年轻人，找一个今晚就能一起遛狗的邻居。**

不是"宠物社交平台"（太虚，面试官记不住），而是一个具体动作：**今晚、附近、一起遛狗**。

## 2. 目标用户

| | 描述 |
|---|---|
| 主要用户 | 22–35 岁、一二线城市、独自养狗、租房、工作日白天没时间 |
| 真实痛点 | 狗需要社交和运动，但一个人遛很无聊；出差/加班时狗没人管；想认识同城养宠的人但没渠道 |
| 使用场景 | 下班后 19:00–21:00、周末上午，在小区附近/公园 |

## 3. 三个构想的统一结构

你的三个想法不是三个功能，是**三层**。这样 1–2 周才能全做出来。

| 你的构想 | 在 v1 里的形态 | 位置 | 成本 |
|---|---|---|---|
| 宠物交友 | 附近宠物卡片流 + 打招呼 | 首页 `/` | 中 |
| 线下宠物聚会 | "遛狗局"：发起 / 报名 | `/meetups` | 中 |
| 宠物品牌活动 | 同一个活动模型，加 `品牌` 标签 + 认证标识 | `/meetups` 的分类页 | **几乎为零** |

关键设计：**用同一张 `Meetup` 表承载"个人遛狗局"和"品牌活动"**，只用一个字段 `type: 'personal' | 'brand'` 区分。品牌活动在列表里是一个筛选标签、一张带认证徽章的卡片——不需要单独做一套系统。

同理，"宠物交友"和"线下聚会"共用同一份宠物档案：你在首页认识一只狗，点进去能看到"它这周六要去哪个局"。

## 4. 核心流程

```
建宠物档案
    ↓
首页刷附近宠物 ──→ 打招呼（已发送）
    ↓                    ↓
看活动列表 ──→ 报名遛狗局 ──→ 圈子里发活动回顾
    ↓
我的：我的宠物 / 我发起的 / 我报名的
```

一个用户从进入到产生内容的路径不超过 3 次点击。演示时能在 90 秒内讲完全流程。

## 5. 信息架构

底部 4 个 Tab（移动端优先）：

```
┌──────────────────────────────────┐
│                                  │
│           页面内容                │
│                                  │
├──────────────────────────────────┤
│  交友   活动   圈子   我的         │
└──────────────────────────────────┘
```

| 路由 | 页面 | 核心内容 |
|---|---|---|
| `/` | 交友 | 附近宠物卡片流、筛选（猫/狗、体型、距离） |
| `/pets/:id` | 宠物主页 | 相册、品种/年龄/体型/性格标签、疫苗绝育、它参加的活动、约遛按钮 |
| `/meetups` | 活动 | Tab：全部 / 遛狗局 / 品牌活动 |
| `/meetups/:id` | 活动详情 | 时间地点、已报名头像、人数上限、体型限制、报名按钮 |
| `/meetups/new` | 发起活动 | 表单：标题、时间、公园、体型限制、人数、说明 |
| `/feed` | 圈子 | 图文动态流、点赞、关联活动 |
| `/me` | 我的 | 我的宠物、我发起的局、我报名的局 |

7 个路由。够撑起一个作品集，又不至于做不完。

- [ ] 我的页面

### P1 — 有余力再加

- [ ] 卡片滑动（左右滑手势）

## 7. 数据模型

```ts
type Pet = {
  id: string
  name: string            // "豆豆"
  species: 'dog' | 'cat'
  breed: string           // "柯基"
  gender: 'boy' | 'girl'
  ageText: string         // "2岁3个月"
  size: 'small' | 'medium' | 'large'
  weightKg: number
  personality: string[]   // ['活泼', '亲人', '爱叫']
  vaccinated: boolean
  neutered: boolean
  photos: string[]
  bio: string
  ownerName: string
  district: string        // "浦东 · 花木"
  distanceKm: number
}

type Meetup = {
  id: string
  type: 'personal' | 'brand'   // ← 一个字段区分遛狗局和品牌活动
  title: string
  cover: string
  hostName: string
  hostAvatar: string
  verified: boolean            // 品牌认证
  startAt: string              // ISO
  venueName: string            // "世纪公园 3 号门"
  district: string
  distanceKm: number
  sizeLimit: ('small' | 'medium' | 'large')[]
  capacity: number
  participants: { name: string; petName: string; avatar: string }[]
  description: string
  tags: string[]
  fee: number                  // 0 表示免费
}

type Post = {
  id: string
  authorName: string
  authorAvatar: string
  images: string[]
  content: string
  meetupId?: string            // 关联到某次活动
  likes: number
  comments: number
  createdAt: string
}
```

## 8. 14 天计划

| 天 | 任务 | 当天结束时应能看到的 |
|---|---|---|
| D1 | 装环境、建项目、**部署上线** | 一个能打开的链接（哪怕只有一行字） |

| D3–4 | 首页宠物卡片流 | 能刷卡片、能筛选 |
| D5 | 宠物详情页 | 点卡片进详情 |
| D6–7 | 活动列表 + 详情 + 报名 | 能报名、人数变化 |
| D8 | 发起活动表单 | 能新增一个局 |
| D9–10 | 圈子动态 + 点赞 | 能刷动态 |
| D11 | 我的页面 | 三个板块 |

## 9. 演示数据策略

社交产品最怕打开是空的。必须有看起来真实的种子数据：

- **30 只宠物**：不同品种、体型、性格，照片用 Unsplash 的宠物图
- **8 个活动**：6 个个人遛狗局 + 2 个品牌活动（比如"XX 宠物粮 · 夏日泳池派对"）
- **15 条动态**：大部分关联到某个活动，形成"活动 → 回顾"的闭环

这不是作弊，是产品演示的标准做法。面试时也能顺势讲"冷启动阶段怎么用种子内容解决空城问题"。

**照片素材**：Unsplash / Pexels 的免费宠物图，直接用图片 URL 引用，不下载。

## 10. 面试时怎么讲

准备四个问题的答案，比功能更重要：

1. **为什么做这个？** 你自己或身边人遛狗的真实困扰
2. **为什么先做活动而不是匹配？** 单边就能成立，绕过冷启动——这是产品判断
3. **最难的是什么？** 说一个具体的坑和你怎么解决的
4. **如果继续做？** 给 3 条 Roadmap：真实登录与数据库、地图找局、品牌方自助发活动

把这份文档和每天的决策记下来，就是"思考的证据"。

## 11. 风险与取舍

| 风险 | 对策 |
|---|---|
| 三个都做 → 每个都浅 | 接受。但保持一条主线：卡片是门面，活动是骨架，圈子是收尾 |
| 1–2 周做不完 | 砍顺序：圈子 → 发起活动 → 筛选。核心"卡片 + 活动报名"必须留 |
| 视觉像半成品 | D13 留一整天专门打磨，不要省 |
| 卡在环境配置 | D1 单独拿出来解决，完成后再写业务代码 |
